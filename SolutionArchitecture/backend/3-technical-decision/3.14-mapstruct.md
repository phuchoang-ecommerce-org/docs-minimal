# MapStruct

Required by [Adjust Content - 2](inkdrop://note/Pso19weS), revision 14. Use generated mappings for structural data conversion at adapter boundaries. Domain construction, authentication, money calculation and state transitions remain explicit code. Before implementing a mapper, fill the [automated test scenario template](../4.%20Automated%20Testing/4.%20Automated%20Testing.md) and write its tests.

## Java mapping example

This UC-04 mapper handles payload fields only. Each public type belongs in its own file; project handler types are omitted. Records need no Lombok constructor generation.

```java
record CheckoutRequest(java.util.UUID addressId, long cartVersion, String voucherCode, String paymentMethod) {}
record CheckoutPayload(java.util.UUID addressId, long cartVersion, String voucherCode, String paymentMethod) {}
record OrderView(java.util.UUID id, java.math.BigDecimal totalUsd, String status) {}
record OrderResponse(java.util.UUID id, java.math.BigDecimal totalUsd, String status) {}

@org.mapstruct.Mapper(
    componentModel = "spring",
    injectionStrategy = org.mapstruct.InjectionStrategy.CONSTRUCTOR,
    unmappedTargetPolicy = org.mapstruct.ReportingPolicy.ERROR,
    typeConversionPolicy = org.mapstruct.ReportingPolicy.ERROR,
    builder = @org.mapstruct.Builder(disableBuilder = true))
interface OrderWebMapper {
  CheckoutPayload toPayload(CheckoutRequest request);
  OrderResponse toResponse(OrderView view);
}

// Facade has a handwritten constructor even when a mapper is injected.
final class OrdersFacade {
  private final OrderWebMapper mapper;
  OrdersFacade(OrderWebMapper mapper) { this.mapper = java.util.Objects.requireNonNull(mapper); }
  CheckoutPayload payload(CheckoutRequest validatedRequest) {
    return mapper.toPayload(validatedRequest);
  }
  // Handler invocation separately receives trusted Actor, route ID and Idempotency-Key.
}
```

MapStruct may generate its own dependency constructor; the prohibition in the user's note concerns using Lombok to generate constructors. `uses` lists only boundary-local helper mappers. Shared configuration may be a compile-time mapping config, not a shared business converter that creates module cycles.

Use explicit named conversions for Money/typed IDs and fail on precision loss. Specify required-null rejection in validation; absent and null PATCH values must remain distinct. Do not apply `@MappingTarget` to a root to bypass `cancel`, `recordCod` or owner checks. A PATCH adapter maps a presence-aware intent, then the handler invokes behavior. Explicitly ignored target fields require a documented reason and a test, not global IGNORE.

## Setup and checks

Declare matching pinned `org.mapstruct:mapstruct` and `mapstruct-processor` versions, the latter on Gradle `annotationProcessor`; add test annotation processing only if test sources declare mappers. If Lombok-generated accessors are mapper inputs, include `lombok-mapstruct-binding` on the processor path. Do not hand-edit generated sources. MapStruct's [reference guide](https://mapstruct.org/documentation/stable/reference/html/) documents these generation options; [Lombok integration](https://mapstruct.org/faq/) describes processor coordination.

Tests precede implementation: null/optional fields; exact USD values and identifiers; no credentials in response; partial-update absence; unknown enum; a new unmapped target field must fail compilation. Test generated mapper behavior, not a mocked mapper. Check all generated classes remain in the originating adapter package. Compile examples in the real project once its dependency matrix is pinned; this document does not claim they have been compiled here.
