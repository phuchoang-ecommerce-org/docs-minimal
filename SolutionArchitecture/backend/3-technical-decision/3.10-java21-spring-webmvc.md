# Java 21, Spring Boot and Spring WebMVC

Status: proposed implementation decision for [roadmap section 3](inkdrop://note/uUXxpSnh), revision 83, read through MCP on 2026-11-07. Java examples show implementation slices, not a compiled backend. 

Java 21 is the toolchain and runtime target. Use Spring Boot, servlet Spring WebMVC, Bean Validation, Spring Security and JDBC for REST HTTP/JSON. The documentation reader's Astro/Tailwind dependencies are tooling, not the application stack. Java 21 records suit request/result values; domain roots remain behavior-rich classes.

Select exact Boot/Modulith/JMolecules patches together during bootstrap, lock them in Gradle, then compile and run the architecture test. Do not select snapshots or use `latest`. The [Boot system requirements](https://docs.spring.io/spring-boot/system-requirements.html) must match the wrapper and Java 21; this documentation does not claim a dependency matrix has already been compiled.

```java
@org.springframework.boot.autoconfigure.SpringBootApplication
public class MarketplaceApplication {
  public static void main(String[] args) {
    org.springframework.boot.SpringApplication.run(MarketplaceApplication.class, args);
  }
}

// Separate file: public fields match OpenAPI; PlaceOrderUseCase/ActorResolver are project ports.
record CreateOrderRequest(@jakarta.validation.constraints.NotNull java.util.UUID addressId,
                          String voucherCode,
                          @jakarta.validation.constraints.Pattern(regexp="COD")
                          @jakarta.validation.constraints.NotNull String paymentMethod) {}

@org.springframework.web.bind.annotation.RestController
class OrdersController {
  private final PlaceOrderUseCase place;
  private final ActorResolver actors;
  OrdersController(PlaceOrderUseCase place, ActorResolver actors) {
    this.place = place; this.actors = actors;
  }
  @org.springframework.web.bind.annotation.PostMapping("/orders")
  @org.springframework.security.access.prepost.PreAuthorize("hasRole('MEMBER')")
  org.springframework.http.ResponseEntity<OrderResult> create(
      @jakarta.validation.Valid @org.springframework.web.bind.annotation.RequestBody CreateOrderRequest body,
      @org.springframework.web.bind.annotation.RequestHeader("Idempotency-Key") String key) {
    var result = place.execute(body, key, actors.currentMember());
    return org.springframework.http.ResponseEntity.created(
      java.net.URI.create("/orders/" + result.id())).body(result);
  }
}
```

The handler persists/replays the original result; reconcile replay response status with OpenAPI. Controllers do not open ad-hoc JDBC connections. Use `@RestControllerAdvice` to map errors to the existing `problem+json` fields (`code`, `message`, `correlationId`, field errors); do not substitute a different envelope. Validate request size, page size and image uploads at the edge and invariants in the domain.

Gradle setup: Java toolchain 21; Boot MVC, validation, JDBC, Security/resource-server, Flyway/PostgreSQL starters/libraries; PostgreSQL driver runtime; Boot-managed test libraries. Use the Modulith BOM for its artifacts and a compatible jMolecules BOM. Boot 4 starter coordinates must be verified against the selected release. No WebFlux, JPA, Redis or Kafka is required. Test MVC validation, 401/403/404 and transaction rollback before E2E.

Use [MapStruct](./3.14-mapstruct.md) for request payload/result DTO conversion in the web adapter. Validate the request first; supply actor/route/header facts explicitly. Add MapStruct/Lombok processors and handwritten constructors per [Lombok policy](./3.15-lombok.md). The test baseline must preserve the requested JUnit 5; do not silently inherit JUnit 6 from a newer Boot test BOM. Verify a compatible pinned combination during bootstrap.
