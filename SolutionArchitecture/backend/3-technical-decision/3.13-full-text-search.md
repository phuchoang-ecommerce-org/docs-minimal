# Full-Text Search

Catalog discovery (UC-01) uses PostgreSQL generated tsvector plus GIN, already included in V1. Use the same explicit text configuration for indexing and querying; PostgreSQL documents stored generated search vectors and GIN indexing in [text search tables](https://www.postgresql.org/docs/18/textsearch-tables.html).

```sql
-- Included in V1, shown here for the design:
-- search_document tsvector GENERATED ALWAYS AS (
--   setweight(to_tsvector('simple', coalesce(title,'')), 'A') ||
--   setweight(to_tsvector('simple', coalesce(description,'')), 'B')) STORED
-- CREATE INDEX product_search_idx ON marketplace.product USING gin(search_document);

WITH input AS (
  SELECT websearch_to_tsquery('simple', :search_text) AS query
), matches AS (
  SELECT p.id, p.title, ts_rank_cd(p.search_document, i.query) AS rank
  FROM marketplace.product p
  JOIN marketplace.seller_shop s ON s.id=p.seller_id
  CROSS JOIN input i
  WHERE p.published AND s.status='ACTIVE'
    AND p.search_document @@ i.query
    AND (:category_id::uuid IS NULL OR p.category_id=:category_id::uuid)
)
SELECT id, title, rank FROM matches
WHERE (:cursor_rank::real IS NULL OR (rank, id) < (:cursor_rank::real, :cursor_id::uuid))
ORDER BY rank DESC, id DESC
LIMIT :fetch_limit;
```

Use NamedParameterJdbcTemplate for the named binds, with explicit Java types; no string concatenation of search text. The `simple` configuration is an approved language-neutral baseline without stemming or accent folding. It does not claim Vietnamese linguistic search quality. Decide corpus/language behavior with BA before adding dictionaries or extensions; no Elasticsearch is needed.

Blank text uses the bounded non-search discovery query. Cap text length/page size, set a query timeout and handle queries containing no searchable lexemes as an empty result. Public results always recheck Seller activation and publication. Query results compose current price, inventory and visible reviews via Discovery rather than creating a Catalog → Review module cycle.

Rank cursors bind the exact search/filter fingerprint and preserve rank precision; changing product text can change rank between pages. For a stable ID-ordered search page, choose ID ordering instead and state the relevance tradeoff. Do not promise stable relevance snapshots across requests. Verify with EXPLAIN (ANALYZE, BUFFERS) on realistic data, including selective and broad terms; small tables may correctly use a sequential scan.

Tests: inactive Seller/unpublished Product excluded, title weighting, punctuation input, no-result/blank query, parameter injection attempt, equal ranks and text changes. Search updates with Product writes through the generated column; no asynchronous indexing job is required.
