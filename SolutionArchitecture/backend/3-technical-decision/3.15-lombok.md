# Lombok

Required by [Adjust Content - 2](inkdrop://note/Pso19weS), revision 14. Use Lombok narrowly for field-level getters on adapter data holders and logging in adapters. All service, handler, adapter and domain constructors are handwritten. Java records are preferred for DTO/value carriers when their semantics fit.

| Allowed use | Scope | Guard |
| --- | --- | --- |
| `@Getter` on a selected immutable field | Adapter-local row/view holder where a record is unsuitable | No getter for credentials; return defensive copies for mutable values |
| `@Slf4j` | Adapter or application operational logging | Log correlation/resource IDs only; never credentials, tokens, full requests or personal data |
| Explicit constructor / factory | Every class with dependencies or invariants | Constructor checks are visible in source; no Lombok shortcut |

Do not use `@NoArgsConstructor`, `@RequiredArgsConstructor`, `@AllArgsConstructor`, `@Data`, `@Value`, `@Builder` or `@SuperBuilder` to construct project classes. The project adopts a ban on those compound/construction annotations to make the user's constructor requirement unambiguous. `@Data` includes a constructor and other generated behavior, as described in [Lombok Data](https://projectlombok.org/features/Data). Root setters, generated equality and broad toString are also excluded: they can bypass invariants or expose sensitive state.

```java
final class StockRow {
  @lombok.Getter private final java.util.UUID variantId;
  @lombok.Getter private final int onHand;
  @lombok.Getter private final long version;

  StockRow(java.util.UUID variantId, int onHand, long version) {
    this.variantId = java.util.Objects.requireNonNull(variantId);
    if (onHand < 0 || version < 0) throw new IllegalArgumentException("stock row");
    this.onHand = onHand;
    this.version = version;
  }
}
```

The corresponding MapStruct input exposes getters; SQL conversion remains in RowMapper. Domain roots retain explicit behavior/accessors and named factories. jMolecules annotations remain semantic declarations, not generation tools. See [Getter behavior](https://projectlombok.org/features/GetterSetter).

## Build policy

Use pinned Lombok on `compileOnly` and `annotationProcessor`, with test equivalents only when tests actually use Lombok. Keep annotation processing enabled in clean CI builds. Include the MapStruct binding when both processors cooperate.

```properties
# lombok.config at the implementation repository root
config.stopBubbling = true
lombok.noArgsConstructor.flagUsage = error
lombok.requiredArgsConstructor.flagUsage = error
lombok.allArgsConstructor.flagUsage = error
lombok.data.flagUsage = error
lombok.value.flagUsage = error
lombok.builder.flagUsage = error
```

Add a Java source/AST policy check covering the banned annotations, including fully qualified names, `SuperBuilder` and static imports/aliases if applicable. Do not claim an ArchUnit annotation check proves the absence of Lombok annotations: SOURCE-retained annotations may not survive compilation. Lombok's [constructor flags](https://projectlombok.org/features/constructor) do not catch constructors generated indirectly by every other annotation.

Before implementing a class using Lombok, write its scenario and behavior test. Verify invalid constructor arguments fail, getters expose only intended fields and logging omits sensitive values. A negative compiler/source fixture containing `@RequiredArgsConstructor` and another containing `@Data` must fail the build policy. Do not add empty no-arg constructors just to satisfy a mapper or mock framework.
