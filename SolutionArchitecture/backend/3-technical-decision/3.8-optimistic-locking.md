# Optimistic Locking

Status: Approved implementation decision for [roadmap section 3](inkdrop://note/uUXxpSnh), revision 83, read through MCP on 2026-11-07. Java examples show implementation slices, not a compiled backend.

Use explicit `version` checks with JdbcTemplate for detached edits: Seller price/stock updates (UC-06), Member cart/review edits (UC-02/08), Admin moderation (UC-09/10). A stale request fails with a conflict and current data is reloaded; do not silently overwrite another edit. This supplements the conditional stock decrement and shared order lock required for UC-04/05/07.

```java
void changeStock(org.springframework.jdbc.core.JdbcTemplate jdbc,
                 java.util.UUID variantId, java.util.UUID sellerId,
                 int onHand, long expectedVersion) {
  if (onHand < 0) throw new IllegalArgumentException("negative stock");
  int rows = jdbc.update("""
    UPDATE marketplace.stock s SET on_hand=?, version=version+1
    WHERE s.variant_id=? AND s.version=? AND EXISTS (
      SELECT 1 FROM marketplace.variant v JOIN marketplace.product p ON p.id=v.product_id
      WHERE v.id=s.variant_id AND p.seller_id=?)
    """, onHand, variantId, expectedVersion, sellerId);
  if (rows != 1) throw new org.springframework.dao.OptimisticLockingFailureException("Stock changed");
}
```

Before this write, perform an owner-filtered lookup: missing/foreign resource is 404. If that lookup succeeds but the conditional update loses a race, return 409 without disclosing foreign data. Every stock writer, including checkout and cancellation, increments version. Under plain JdbcTemplate, a `@Version` annotation alone performs no version check.

The [HTTP contract](../../api-contract/http-api.md) now selects response `version` and required `expectedVersion` for edits (JSON body; query parameter for DELETE). Missing/invalid version returns 400; an owned stale version returns 409. Product version guards variant-price/image changes; stock keeps its own version. A stale absolute stock count must not be retried automatically: reload and ask the operator to reapply intent. Payment/cancellation retain root-row serialization and state checks, not a generic retry of an illegal transition.

Test: two edits share version N, only one succeeds; checkout increments version and rejects a stale Seller stock replacement; foreign ID yields 404.
