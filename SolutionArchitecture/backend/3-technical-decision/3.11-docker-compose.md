# Docker Compose

Use Compose for disposable local PostgreSQL and the backend API. The example assumes the target `backend/` tree, a built `app/build/libs/marketplace.jar`, and local gitignored `.env` values. It is a dev setup, not a production secrets/backup plan. No Redis, message broker or image store is added.

```dockerfile
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY app/build/libs/marketplace.jar /app/marketplace.jar
USER 10001:10001
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app/marketplace.jar"]
```

```yaml
name: marketplace-dev
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_DB: marketplace
      POSTGRES_USER: marketplace_dev
      POSTGRES_PASSWORD: ${DB_PASSWORD:?set local DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U marketplace_dev -d marketplace"]
      interval: 5s
      timeout: 3s
      retries: 20
    ports:
      - "127.0.0.1:5432:5432"
  api:
    build: .
    depends_on:
      db:
        condition: service_healthy
    environment:
      SPRING_PROFILES_ACTIVE: dev
      DB_URL: jdbc:postgresql://db:5432/marketplace
      DB_RUNTIME_USER: marketplace_dev
      DB_RUNTIME_PASSWORD: ${DB_PASSWORD:?set local DB_PASSWORD}
      DB_MIGRATION_USER: marketplace_dev
      DB_MIGRATION_PASSWORD: ${DB_PASSWORD:?set local DB_PASSWORD}
      JWT_PRIVATE_KEY_PATH: /run/secrets/jwt_private
      JWT_PUBLIC_KEY_PATH: /run/secrets/jwt_public
    secrets: [jwt_private, jwt_public]
    ports:
      - "127.0.0.1:8080:8080"
    read_only: true
    tmpfs: [/tmp]
secrets:
  jwt_private:
    file: ${JWT_PRIVATE_KEY_FILE:?set key path}
  jwt_public:
    file: ${JWT_PUBLIC_KEY_FILE:?set public key path}
volumes:
  pgdata:
```

`JWT_*_PATH` are proposed application config keys: implement a key-loading bean and fail startup if absent; Spring does not infer a signer from these names. Secret files must be readable by container UID 10001 without being committed. Set `bootJar.archiveFileName` to `marketplace.jar`. Pin image digests in the implementation's deployment lock after validation.

```sh
./gradlew :app:bootJar
# Supply gitignored local variables and keys, then:
docker compose config --quiet
docker compose up --build -d
# Check normal login and a public catalog endpoint after migrations complete.
docker compose down
```

Health-gated ordering waits for the database, not merely its process start. [Compose startup guidance](https://docs.docker.com/compose/how-tos/startup-order/). API readiness follows Flyway completion and successful startup; add a restricted readiness endpoint if needed. `down` retains data; do not add `-v` to routine commands.

Production uses the prod profile, separate migration/runtime roles, deployment secrets, TLS at ingress, no published database port, backups and no synthetic seed. This local database owner account is never the production runtime account. Frontend is built separately with its existing pnpm/Next.js profile contract; its server forwards to the API internal address.
