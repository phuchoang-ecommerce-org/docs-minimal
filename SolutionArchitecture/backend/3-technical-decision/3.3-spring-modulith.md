# Spring Modulith

Status: Approved implementation decision for [roadmap section 3](inkdrop://note/uUXxpSnh), revision 83, read through MCP on 2026-11-07. Java examples show implementation slices, not a compiled backend.

Use explicitly annotated modules, closed internal packages and named public APIs. The [Modulith module model](https://docs.spring.io/spring-modulith/reference/fundamentals.html) supports declared dependencies; [verification](https://docs.spring.io/spring-modulith/reference/verification.html) detects cycles and access to internals.

```properties
spring.modulith.detection-strategy=explicitly-annotated
```

```java
// ordering/package-info.java
@org.springframework.modulith.ApplicationModule(allowedDependencies = {
  "shared", "identity :: api", "catalog :: api", "inventory :: api",
  "cart :: api", "promotion :: api", "audit :: api"
})
package com.example.marketplace.ordering;

// ordering/api/package-info.java (separate file)
@org.springframework.modulith.NamedInterface("api")
package com.example.marketplace.ordering.api;

// architecture/ModuleStructureTest.java
class ModuleStructureTest {
  @org.junit.jupiter.api.Test
  void modulesRespectBoundaries() {
    org.springframework.modulith.core.ApplicationModules
      .of(com.example.marketplace.MarketplaceApplication.class).verify();
  }
}
```

Annotate every module listed in [the module catalog](./3.1-modular-monolith.md); otherwise explicit detection can miss it. Export only DTOs/commands/query interfaces in `api`. Keep shared immutable API types in the Shared module's public base package or explicitly name its subinterfaces.

```java
// ordering/OrderingModuleTest.java
@org.springframework.modulith.test.ApplicationModuleTest
class OrderingModuleTest {
  // Replace exported collaborators with test doubles for isolated behavior.
  // Run full PostgreSQL tests separately for checkout atomicity across modules.
}
```

Use `spring-modulith-starter-core` and test-scoped `spring-modulith-starter-test`, managed by the Modulith BOM compatible with the chosen Boot line. Pin exact versions during bootstrap and record a successful compile/module test; the [compatibility appendix](https://docs.spring.io/spring-modulith/reference/appendix.html) alone does not prove the selected combination. Do not enable event persistence or asynchronous listeners for mandatory stock/payment/audit writes. Local domain facts remain provisional until commit.

Keep generated MapStruct implementations inside the declaring adapter package, not a new public named interface. Include generated production classes in module checks. [Section 4](../4-automated-testing/4.%20Automated%20Testing.md) requires expected-module inventory plus negative boundary fixtures before feature implementation.
